# Page Reports on Templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The five built-in page PDFs (Data Report, Instrument Trend, Instrument Alarms, Alarm Report, Audit Trail) are drawn by the same template model as widget reports — administered per profile (or application-wide) on Configuration → Report Templates — and every report now freezes its chrome (snapshot v3).

**Architecture:** One vocabulary of *template kinds* (`TemplateKind = WidgetType | PageTemplateKind`) replaces `widgetType` across shared, API, and web; the `report_templates.widget_type` column is renamed `kind` and `profile_id` becomes nullable for the two application-wide kinds. `buildWidgetReport` is generalised into `buildTemplatedReport` (sections with notes, images, bold grids and page breaks), the five page builders become pure row builders feeding it, and `createReport` resolves the chrome up front for every report so `getSnapshot` always writes v3.

**Tech Stack:** TypeScript, Fastify 5 + Prisma 6 + PostgreSQL 18 (API), React 19 + SWR + jsPDF 4.2.1 (web), zod (shared), vitest (one web file per process, API single fork on `compliance_core_db_test`).

**Spec:** `docs/superpowers/specs/2026-11-03-page-reports-on-templates-design.md` (§15 = the controller's calls).

## Global Constraints

- Download kinds (`REPORT_KINDS`, 22) are UNCHANGED; Report Settings, approvers, audit `reportType`, `reportTypeMatchesKind` are untouched. Only `templateKindOf(downloadKind)` maps to a template kind (spec §4).
- The wire field, query parameter, Prisma field and column are `kind`; nothing new speaks `widgetType` (spec §5.1).
- `profile_id` NULL = application-wide; unique indexes use `COALESCE(profile_id, '')` (spec §5.3). The API refuses scope mismatches with 400 `SCOPE_MISMATCH` (spec §5.4, §7).
- `key:` columns are NOT offered to any page kind; `attr:` only to the three per-profile page kinds (spec §4 `profileFields`).
- A cell that is a string prints verbatim; a template's `decimals` never re-rounds it (widget rule C1, spec §3 anti-goals).
- The built-in template of each page kind reproduces today's layout exactly, pinned by frozen fixtures captured from the OLD builders before they are deleted (spec §3 G2, §12).
- Every `getSnapshot()` writes `version: 3` with `chrome`; v2 stays readable (spec §9).
- Placeholders are appended to `REPORT_PLACEHOLDERS`, never renamed; each kind lists the ones it supplies (spec §6).
- Every write path stays SUPER_ADMIN by role + re-auth `UPDATE_REPORT_TEMPLATE` + audit `REPORT_TEMPLATE_*` (spec §11). HTML stripped on write as today.
- Tests: web files one per process by exit code; API e2e single fork on the test DB; mutation-check every new rule named below; tsc ×3 and lint clean before hand-over. Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Counts that move: migrations +1. Models 40, modules 27, routes 57, config pages 24, defs 37, type files 40, reauth 58, audit 105/118 unchanged.
