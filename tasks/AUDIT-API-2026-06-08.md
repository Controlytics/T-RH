# API Route Protection Audit — 2026-06-08

READ-ONLY audit. No source modified. Scope: every Fastify route-defining file mounted in
`apps/api/src/app.ts`, plus the auth/rbac plugins and key services consulted to verify behaviour.

## Conventions (verified against source)

- **AuthN**: global `onRequest` hook in `apps/api/src/plugins/auth.ts` enforces a valid JWT on
  every request EXCEPT the explicit allowlists:
  - `PUBLIC_PATHS` (all methods): `/api/auth/login`, `/api/auth/forgot-password`,
    `/api/auth/beacon-logout`, `/api/health`, `/docs` (non-prod), `/api/internal/mqtt`,
    `/api/ws`, `/api/notification-settings/email/oauth2/code`, `/api/data/telemetry|attributes|binary|event`.
  - `PUBLIC_GET_PATHS` (GET only): `/api/config/branding`, `/api/config/datetime/current`,
    `/uploads/photos/`, `/uploads/branding/`, `/api/roles/active`, `/api/admin-requests/user-lookup`.
  - `POST /api/admin-requests` (exact) — public submit.
- **AuthZ**: `app.requirePermission('X')` / `app.requireAnyPermission(...)` / `app.requireRole(...)`
  / `app.requireSuperAdmin()` in `preHandler`. SUPER_ADMIN bypasses all permission checks
  (`apps/api/src/plugins/rbac.ts`). `*_VIEW <- *_READ` and `*_<suffix> <- *_MANAGE` implication
  applies.
- **Reauth**: `enforceReauth('ACTION', req, reply)` (config-driven; can be disabled per-action by
  admin) or `enforceReauthAlways(...)` (hard-coded password gate) inside the handler.
- **Validation**: Fastify JSON `schema` (body/params/querystring). Fastify strips unlisted fields.

Coverage note: the file set is `**/routes.ts` + `assets/routes/*.routes.ts` + config
`static-routes/*` + `dynamic-routes.ts` + the transport routes (`mqtt-auth-routes.ts`,
`mosquitto-refresh-routes.ts`, `ws-handler.ts`) + `queries/*.routes.ts` +
`data-ingestion/debug-trace.routes.ts` + `pm-schedules/execution-routes.ts` +
`filter-operations/events-routes.ts`. All mount points cross-checked against the
`app.register(...)` block in `app.ts` (lines 307–355). No route surface left unaudited.

## Findings — observations

1. **No route mutation found with zero authorization.** Every state-changing endpoint has a
   `requirePermission` / `requireAnyPermission` / `requireRole` / `requireSuperAdmin` gate, or is an
   intentional public/self-scoped/device-token/shared-secret path. There are **no NO_AUTHZ findings**.
2. The dominant real gap class is **destructive/high-trust mutations that skip `enforceReauth`** while
   sibling mutations in the same module reauth. Severity varies by blast radius (see TOP 15).
3. Schema coverage is strong; the only `NO_SCHEMA` cases are `reports` GET/DELETE handlers (no params
   schema on the DELETE) and a few `:id/toggle` bodies — all permission-gated, low impact.

---

## TOP 15 most concerning gaps (prioritized)

1. **PUT /api/config/users/:userId** — `config/static-routes/roles.routes.ts:133`. Grants per-user
   permission OVERRIDES (`permissions: {key: boolean}`), sidebar, and home-widgets, gated only by
   `CONFIG_UPDATE` with **NO reauth**. A privilege-escalation surface: any role holding the generic
   config-edit permission can mint arbitrary permissions onto any user (including themselves) with no
   password challenge. **Highest priority** — should require reauth and arguably a dedicated
   permission distinct from generic config edit.

2. **POST /api/retention/execute-range** — `queries/retention.routes.ts:265`. SUPER_ADMIN/ADMIN, no
   reauth. Irreversible bulk DELETE of TSDB telemetry/attributes/events/checklist rows across a time
   range (and cascades to `checklistReview` PG rows). Sibling `POST /retention/execute` (line 200) DOES
   reauth — inconsistent. ADMIN (not just SUPER_ADMIN) can wipe compliance time-series with only a
   `confirmed:true` body flag.

3. **POST /api/retention/delete-records** — `queries/retention.routes.ts:451`. SUPER_ADMIN/ADMIN, no
   reauth. Deletes individual telemetry/attribute history records by (time,key). Irreversible,
   audit-relevant data, no password gate.

4. **POST /api/retention/delete-keys** — `queries/retention.routes.ts:376`. SUPER_ADMIN/ADMIN, no
   reauth. Deletes ALL data for given keys on an entity (TSDB + latest cache). Irreversible, no
   password gate.

5. **POST /api/connectivity/:entityId/token** — `connectivity/routes.ts:263`. SUPER_ADMIN/ADMIN, no
   reauth. Generates/rotates (or sets a CUSTOM) device access token — a credential that grants MQTT/HTTP
   ingest. Credential mint should be reauth-gated (compare: every user-credential mutation in users/
   reauths).

6. **DELETE /api/connectivity/:entityId/token** — `connectivity/routes.ts:371`. SUPER_ADMIN/ADMIN, no
   reauth. Revokes a device credential (denial-of-service against a device's ingest). Same posture gap.

7. **DELETE /api/notification-settings/logs/:id** — `notification-delivery/routes.ts:513`. CONFIG_UPDATE,
   no reauth. Deletes a notification DELIVERY LOG record (records of what compliance/alert emails/SMS
   were sent). Record-tampering surface with no password challenge and no in-handler audit emit.

8. **POST /api/notification-rules/:id/test** — `notification-rules/routes.ts:308`. CONFIG_UPDATE, no
   reauth. Fires a real notification dispatch (`dispatchNotification`) for an arbitrary rule — can be
   used to spam configured recipients (email/SMS) on demand. Low data-impact but an abuse/cost vector.

9. **DELETE /api/notification-rules/:id** + **PUT /:id**/**POST /** — `notification-rules/routes.ts:97/169/267`.
   CONFIG_UPDATE, no reauth. Create/edit/delete the rules that govern who gets which compliance alerts;
   silently disabling a rule suppresses notifications. Audited but no password gate.

10. **user-groups POST / , PUT /:id , DELETE /:id (+ member add/remove)** — `user-groups/routes.ts:28/53/76/119/140`.
    CONFIG_UPDATE, no reauth. Group membership feeds notification-rule recipient targeting; editing it
    redirects who receives alerts. Lower trust than the above but same no-reauth class.

11. **dashboards POST / , PUT /:id , DELETE /:id and all widget/assignment mutations** —
    `dashboards/routes.ts:127/172/204/225/266/299/358/391`. Permission-gated (DASHBOARD_*), no reauth.
    Mitigant: module is PARKED (no FE consumer per file docblock), so live exposure is minimal — but the
    routes are registered and reachable by any token with the perm.

12. **PATCH /api/report-templates/:id/toggle-status** — `report-templates/routes.ts:131`. REPORT_TEMPLATE_UPDATE,
    no reauth, while every other mutation in this 21-CFR-adjacent module reauths. Toggling a report
    template ACTIVE/ARCHIVED changes which templates can produce signed PDFs.

13. **PATCH /api/filter-cleaning-profiles/:id/toggle-status** — `cleaning-profiles/routes.ts:168`.
    FCP_UPDATE/CP_PAGE_EDIT, no reauth, while create/update/delete in the same module reauth. A cleaning
    profile drives the cleanroom pipeline; deactivating one is operationally significant.

14. **PUT /api/notification-settings/email|sms templates and POST /templates** — `notification-delivery/routes.ts:534/551/565`.
    CONFIG_UPDATE, no reauth. Notification template bodies are reflected into outbound email/SMS; editing
    them is content-injection-adjacent. (Email/SMS *config* PUTs already reauth — templates are the gap.)

15. **DELETE /api/data/binaries/:entityId** — `data-ingestion/routes.ts:514`. ASSET_DELETE, no reauth.
    Permanently unlinks a binary file from disk + TSDB. Path-traversal is guarded, but the destructive
    file delete has no password challenge while filter retire/replace/delete all reauth.

### Residual notes (not in TOP 15, recorded for completeness)
- **super-admin /data/* edits + filter-data edits have NO application audit trail** by design
  (`super-admin/routes.ts` header docblock). Reauth IS present; the missing audit-of-the-edit is a
  documented, user-accepted 21 CFR §11 residual, not a new finding.
- The `reports` GET/DELETE handlers lack params/querystring JSON schema (NO_SCHEMA), but are
  permission-gated; impact is limited to missing input shape validation on a UUID path param.
- Intentional public endpoints are all accounted for and correctly minimal: login, forgot-password,
  beacon-logout, health, admin-request submit + user-lookup (enumeration-hardened), roles/active,
  config branding/datetime current, OAuth2 callback (output XSS-escaped), MQTT internal callbacks
  (shared-secret / device-token), and /api/ws (in-band JWT).
- Verified NOT vulnerable despite no `requirePermission`: all `/api/notifications` per-id and bulk
  mutations — `notification.service.ts` enforces ownership via `assertNotificationVisible()` and
  repository-level user/role scoping.
