# Floor layout models — client presentation (2026-10-03)

Standalone pages that show the six traced CWH floors (QC, QC Microbiology,
QC 3, Module-E, Module-F Ground and First) in EIGHT visual models, so the
client can choose one. (Four on the first pass; the second pass the same day
upgraded those four — gradient washes, icons, limit bars, glowing alarm rooms,
a hover panel with limits, beacons in 3D — and added four more, on the
operator's "they are so basic".) **Nothing here is wired into the app** — the live
dashboard still draws its own 2D architectural plans; these pages read a
frozen copy of the same traces.

Open `index.html` by double-click. No server, no internet: every page is
plain HTML + SVG, and the 3D page bundles its own copy of three.js in
`vendor/` (r128 UMD, MIT).

| File | Model |
|---|---|
| `model-normal.html` | Normal — flat plan, washed rooms, cards with limit bars |
| `model-heatmap.html` | Thermal heatmap — temperature / humidity field blended across the floor (IDW on a canvas, clipped to the rooms) |
| `model-blueprint.html` | Blueprint — drawing-office sheet, title block, boxed instrument tags |
| `model-dark.html` | Dark control room — glowing walls, big numerals, counters, pulsing alarm rooms |
| `model-isometric.html` | Isometric 2.5D (SVG) — shaded walls, floating cards, beacons |
| `model-3d.html` | 3D interactive (three.js; orbit / zoom / pan / hover; beacons and pulsing rings on alarms) |
| `model-twin.html` | Digital twin 3D — glass partitions, tiled floors, status glow, slow turntable |
| `model-tiles.html` | Tile wall — no geometry; one big tile per instrument, alarms first |
| `thumbs/` | The launcher's previews (one crop per model, regenerated with the screenshots) |
| `Layout-Models.pptx` | The deck: today's 2D, one slide per model, all eight side by side, comparison matrix, decision |

Each page has a floor tab bar (`#floor=<id>` in the URL), the status legend
with the floor's counts, a hover panel on every room (name, ID, both readings
with their limits, the sample note), and a footer. `common.js` holds the geometry every
model draws from — polygon rooms, walls with door gaps cut and the building's
real outline classified by probing both sides, door leaves and swings, the
largest inscribed rectangle a card sits in — and `common.css` the chrome.

## Data

`data/layouts.js` is GENERATED by `apps/api/scripts/export-layout-models.ts`
(`cd apps/api && npx tsx scripts/export-layout-models.ts`, read-only against
the local database). It carries each floor's `ArchLayout` in drawing pixels
plus a **sample snapshot** of readings and limits through
`buildTelemetryOverview()`. For the demonstration the snapshot treats the last
stored reading as current (the local sender is not running, so every
instrument is otherwise "offline"), fills an empty slot with the midpoint of
its limits, and forces a few instruments into out-of-limit / offline /
sensor-fault states so every colour shows. Every such change is listed in the
file (`demoOverrides`, per-reading `demo`) and the pages say "sample snapshot"
in the footer. Re-run the script to refresh the snapshot.

## Screenshots

Headless Chrome does not composite a WebGL canvas into `--screenshot`, so the
3D and twin pages take `?still`, which renders one frame per floor with
`preserveDrawingBuffer` and shows it as an `<img>`. The deck's screenshots were
taken at 1600 x 1000 with
`chrome --headless=new --user-data-dir=<temp> --screenshot=… "model-<m>.html[?still]#floor=<id>"`.
